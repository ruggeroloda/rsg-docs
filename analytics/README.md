## Pitfalls (seen)
- NPM custom config: a regex `{n}` quantifier must be quoted, or the host goes offline.
- Umami reads client-sent IP headers (`True-Client-IP`, `CF-Connecting-IP`, `CF-IPCountry`…) before X-Forwarded-For: 18 % of the first visits had no country, and the headers could dodge `IGNORE_IP`. Fixed 16 Nov 10:33 UTC with `CLIENT_IP_HEADER=x-real-ip` + `SKIP_LOCATION_HEADERS=1` (NPM sets X-Real-IP to the real peer). Sessions before the fix keep their empty country (IPs are never stored).
- WP Rocket JS minify copied the external tracker into `cache/min` on the first live deploy → excluded with `rocket_exclude_js`.
- After an **Umami upgrade**: backup first, pin the new version, read the release notes, check the tracker + recorder paths and `/api/websites/<id>/recorder` still match the NPM config.

- **`rsg.flag`** = unusual moves, good and bad, as of the last Umami day and the last Search Console day. `1d` = the day vs the same weekday of the 4 previous weeks (fallback: previous 7 days); `7d` = the last 7 days vs the 4 weeks before. Counts: Poisson noise + the spread seen in the reference weeks (|z| ≥ 3, ≥ 25 %, a minimum volume); rates: two-proportion test (n ≥ 100 a day / 300 a week); p75s (**markets only** since 22 Nov 2026: `market=in` series; whole-site and `out` p75s stay in `metric_day` unflagged): ≥ 25 % and a Core Web Vitals threshold crossed (or ≥ 50 %); position: ≥ 2 places (1d) / 1 (7d); plus Search Console page moves (7d, pages with ≥ 15 clicks a week, top 30). `severity`: `alert` (strong, bad), `win` (strong, good), `notable`. A count with no row on a built day counts as 0, so a spot dropping to zero clicks is caught.
